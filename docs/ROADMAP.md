# 路线图

> 更新于 2026-10-28（v0.12.3 之后）。标 ⏳ 是计划内，✅ 是已完成，~~删除线~~ 是**明确不做**（列出来是为了不用再讨论一遍）。

## 排序原则

这个工具的全部价值集中在「**计数可信**」一件事上。计数一旦被怀疑，形象、动效、喝水提醒都只是装饰。

v0.9.2–v0.9.5 连续四个版本都在修同一处判定，用户每次反馈都是「数字不对」。所以 v1.0 之前只做两类事：**让计数可信**、**让陌生人装得上**。

到 v0.12.3 这两件事都做完了：判定机有 69 项断言兜着，dmg / 引导 / 图标 / CI 齐了，签名问题用文档兜住。**v1.0 的发布清单已全部完成**（英文界面 2026-10-28 决定不做，见下）。

所以现在的排序原则换成两条：

1. **先把用户已经报过的问题收干净**，不留「下个版本再说」的尾巴
2. **再谈发布**。发布不是终点，是拿真实反馈的起点；功能堆得再满，没人装也没用

## v0.13.0 · 收尾（当前迭代）

v0.12.1–v0.12.3 连着修了三处「看得见但说不清」的毛病（12 秒不游走、游走被误判成拖拽、重影）。这一版把剩下的小尾巴一次收掉，**收完就可以发 v1.0**。

|---|---|---|

| 第三档「终极提醒」 ✅ | 2026-10-28 加。原来 `upgradeToStrong()` 里直接 `startChasing()`，**「强提醒」和「终极提醒」是同一件事，对外说的三档其实只有两档**。现在拆成三档、每档只加一个新行为：软提醒沿下缘游走 → 强提醒停住 + 屏保层级 + 提示音 + 变橙 → 终极提醒变红 + 缓慢跟光标（2.4px/帧、0.055 比例，约 72px/s；原来是 210px/s，光标一动就窜过去）。两条护栏：**光标压在卡片上就停**（否则永远点不着按钮）、**静默不追**。`tick` 里补了追光标的自愈。设置页有开关和升级间隔（默认 5 分钟），菜单有「预览终极提醒」 | 0 |
| 重影修复实机验证 ⏳ | 已改 `layerContentsRedrawPolicy`，但屏幕合成层抓不到图，只能靠人眼确认「坐→站那一下椅子上还有没有留着半只猫」 | 0 |

| 设置页「强提醒 90 分钟时升级」文案 ✅ | 2026-10-28 改。实际条件是「**无响应累计** 90 分钟」（`focusSeconds >= strong` 且卡片一直挂着、且不在静默期），不是「坐满 90 分钟就弹」。新文案「累计 90 分钟仍不理会才升级」，Preview 渲染确认不截断 | 0 |
| 「我去走走了」要确认 ✅ | 2026-10-28 改（用户提的规则）。原来点了就清零 + 打卡，手还放在键盘上也能刷掉一轮。现在点了只算宣称，开 5 分钟观察窗口：熄屏够久或手停够 60 秒才认账，否则累计一秒不减、5 分钟后带「你好像没走开」再弹一次。见 [D-29](DECISIONS.md#d-29--我去走走了是一句宣称不是一道命令) | 0 |
| 动作序列补测试 ✅ | 2026-10-28 改。`AnimTest` 第六段：相邻换帧按**坐姿族 / 站姿族**判定，跨族只准是 `sit→stand` 和 `stand→sitdown`，一段里最多起身一次坐下一次；另外钉住每段都以 `.sit` 开头结尾。配上「新增姿态别忘了归类」的兜底断言 | 0 |

## v1.2 · 功能

**先说优先级**。这四项不是一个权重：

1. **喝水提醒** —— 唯一一项「用户明确要过、但一直没做」的欠账。原始需求第一句就是「提醒我起来走走**和喝水**」，走做完了，水欠了快二十个版本。它该排在所有新功能前面
2. **免打卡额度** —— 习惯机制的完整性。连续天数一旦因为出差断掉，整个解锁体系对用户的激励就归零了，这是机制漏洞不是新功能
3. **久坐曲线** —— 锦上添花。它能让人看到趋势，但看不到也不影响今天站起来
4. **轻提醒形态** —— 体验打磨。现在「静默不升级、不追鼠标」已经能用了，更轻的形态是优化

| 事项 | 说明 |
|---|---|
| **喝水提醒** ⏳ | 欠账，优先做。设计草案见下 |
| 免打卡额度 ⏳ | 每月 2 天「豁免」，手动使用 |
| 今日 / 本周久坐曲线 ⏳ | 纯本地统计，不上传。数据源就是每天的累计秒数，存 `UserDefaults` 环形缓冲 14 天 |
| 轻提醒形态 ⏳ | 静默期间（看视频/线下会）的卡片可以更轻：角落小尺寸、半透明、不占焦点。v0.9.5 只做到「不升级、不追鼠标」 |

**喝水提醒设计草案**（沿用 D-21 的教训，先分清「记账」和「打扰」）：

- 和久坐**分开两个计时器**：坐姿时长 vs 距上次喝水时长
- 喝水是「事件」不是「时长」：点了「我喝了」就重置，不点也不强推
- **不做独立弹窗**，只在久坐卡片里带一句「顺手喝口水」。两个弹窗抢注意力会互相稀释
- 当日喝水次数藏进设置页「习惯」分组

## 更远 / 实验

- **动作补间**：每个动作只有 1 帧关键姿态，靠时序和停顿做「动」的错觉。真做中间帧要 AI 出序列（成本高、一致性差），短期不做
- **Sparkle 自动更新**：v1.0 之后再考虑，先靠 Release 页手动下载
- **Homebrew Cask**：`brew install --cask xiehuier`，需要一个稳定的 dmg URL 和 sha256
- **专注模式联动**：系统开了「勿扰」就自动免打扰。能做，但要在 README 写清是读系统状态而不是读你的通知内容

## 已知缺陷（诚实清单）

这些不是 TODO，是当前实现的天花板，写在 README 里比藏起来好：

| 缺陷 | 原因 | 缓解 |
|---|---|---|
| 线下围坐开会、戴耳机用手机开会 → 检测不到，照常弹提醒 | 会议检测只有「摄像头/麦克风被占用」一条正向证据 | 菜单里「暂停 1 小时」：记账不停、只是不提醒 |
| 人离开但屏幕没熄（没锁屏、还没到熄屏时间）→ 会多记几分钟 | 屏幕状态是唯一可靠的离开信号 | 一般 10 分钟内会熄屏；多记的代价是回来多点一次提醒 |
| 屏幕设成「永不休眠」且人真的走了 → 累计会一直涨，回来手一动就补弹一次 | 拿不到熄屏信号，只剩时长可参考 | 菜单会显示「手停 32 分钟，先不弹」；确实要走开请手动「暂停 1 小时」 |
| 关机一夜回来从 0 开始 | 落盘只续 10 分钟内的快照——久到那个程度，我们真的不知道你中间在不在 | 这是故意的：归零比编造诚实（[D-23](DECISIONS.md#d-23--落盘只续数字不补间隙)） |
| 人走了但屏幕没熄、手也没停过（比如外接键鼠被动过）→ 会被算成坐着 | 没有摄像头/红外，无法直接确认座位上有没有人 | 不做生物检测是产品选择，见下方「明确不做」 |
| 坐 ↔ 站之间仍有一步硬切 | 素材只有「坐下」的中间态 `sitdown`，没有能用的「起身」帧。`sit` 里动物坐在椅子中央，`stand` 里动物站在椅子右侧，切换时位移和起身同时发生。橘猫出过一版 `standup`（v0.12.6），实机读起来是「蹲下去」不是「站起来」，已撤下 | 靠缩短收尾时长（0.30 → 0.20s）让硬切不刺眼；重出图见 v0.13.0 待办 |
| 水獭素材左边被切 | `b/sit.png` 在 x=0 这一列有 242/512 行是不透明的——AI 出图时身体画出了画布。v0.12.8 之前宠物底下垫着圆盘，圆形裁剪把它伪装成「圆形肖像」的边界；圆盘去掉后就是一条直边 | 换回其它形象；或重出 b 的素材（出图时要求「完整入画、四周留白」） |
| `docs/images/gaze-at-real-size.png` 是旧卡片样式 | 图里还是带圆盘的卡片。内容是四向视线对比，结论没变，只是样式过时 | `Preview` 工具没暴露 `model.gaze`，要重出得先加参数 |
| 动作只有关键姿态，没有真正的中间帧 | AI 出图的成本与一致性风险决定了这一点。一帧关键姿态 + 停顿节奏拼出「动」的错觉 | 这是 2D 逐帧的常规做法，不算缺陷；但要求「真的流畅」就得做补间，见「更远」 |

## 明确不做

| 事项 | 理由 |
|---|---|
| ~~全屏半透明遮盖~~ | 打断工作，会议共享屏幕时尤其糟糕。见 [D-12](DECISIONS.md#d-12--强提醒不做全屏遮盖改贴光标) |
| ~~Windows / Linux 版~~ | 核心依赖全是 macOS 专有行为（NSPanel 不抢焦点、`CGEventSource`、`.screenSaver` 层级、LaunchAgent），移植等于重写 |
| ~~读取你在用哪个 App~~ | 需要额外权限，且超出「提醒站起来」这个目标 |
| ~~摄像头 / 红外判断座位上有没有人~~ | 隐私成本远超收益。屏幕亮不亮已经是足够的替身信号（见 [D-19](DECISIONS.md#d-19--用屏幕状态替代时长猜测)） |
| ~~云同步打卡记录~~ | 引入账号和后端，和「零权限、纯本地」的定位冲突 |
| ~~App Store 上架~~ | 需要 App Sandbox，而 `CGEventSource` 空闲时长和 LaunchAgent 自启在沙盒下都受限 |
| ~~让用户自定义上传宠物图片~~ | 动作一致性极难保证（没对齐的图切帧会跳），会变成一堆「为什么我的猫在闪」的 issue |
