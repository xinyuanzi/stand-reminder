# 路线图

> 更新于 2026-10-27（v0.9.5 之后）。标 ⏳ 是计划内，✅ 是已完成，~~删除线~~ 是**明确不做**（列出来是为了不用再讨论一遍）。

## 排序原则

这个工具的全部价值集中在「**计数可信**」一件事上。计数一旦被怀疑，形象、动效、喝水提醒都只是装饰。

v0.9.2–v0.9.5 连续四个版本都在修同一处判定，用户每次反馈都是「数字不对」。所以 v1.0 之前只做两类事：**让计数可信**、**让陌生人装得上**。新功能一律往后放。

## v0.9.6 · 让计数可信

| 事项 | 要解决的问题 | 做法 | 验收 |
|---|---|---|---|
| 计时落盘 ⏳ | 重启 app 归零，是唯一还没堵住的「莫名归零」 | 每 10 秒 + 退出时写 `UserDefaults`，启动时按写入时间戳决定是否续上（超过 4 小时不续） | 重启后进度不变；关机一夜回来从 0 开始 |
| 判定状态机抽出来 + 时间轴测试 ⏳ | 四个版本改在同一处，每次都靠「重启 → 盯着菜单栏」手测 | 把 `(idle, isAway, meetingBusy) → (累加 / 清零 / 暂缓 / 静默)` 抽成纯结构体 `PresenceMachine`，输出放 `Tools/PresenceTest`，用时间轴用例表跑 | 用例表覆盖：锁屏 5 秒 / 锁屏 40 秒 / 看视频 50 分钟 / 会议 60 分钟 / 合盖 8 小时 / 跨零点 / 屏幕永不休眠 |
| 全屏 Space 实测 ⏳ | 卡片配了 `.fullScreenAuxiliary`，但从没在全屏视频/Keynote 下验过 | 全屏播视频，看提醒是否浮出、是否落在正确屏幕 | 全屏视频与全屏演示下都能看到卡片；不跑到别的 Space |
| 菜单显示今日累计 ⏳ | 只有「连续专注 X 分钟」，看不出这一天到底坐了多久 | 菜单加一行「今日累计 3 小时 20 分（含 2 次休息）」，跨零点归零 | 数字随计时增长；点「我去走走了」后累计不倒退 |

## v1.0 · 能发给别人

发布阻塞项，缺一个都不算「开源可下载」。

| 事项 | 说明 |
|---|---|
| 应用图标 ⏳ | **现在连 `CFBundleIconFile` 都没有，Finder 里是空白图标。** 用猫头鹰定妆照裁一版 `.icns`（16–1024 全尺寸） |
| 代码签名 + 公证 ⏳ | 不做的话，别人下载后会被 Gatekeeper 拦。两条路：① Apple Developer 账号签名公证（¥688/年）；② 不签名，README 里给 `xattr -dr com.apple.quarantine` 一行命令，并说明为什么 |
| `.dmg` 发 Releases ⏳ | 依赖上一条。用 `hdiutil` 打包，附版本号与 changelog 摘要 |
| 首次启动引导 ⏳ | 现在只是自动弹设置页。改成三屏：它是什么 / 为什么不需要任何权限 / 三个最该调的设置 |
| 英文界面 ⏳ | 文案全部硬编码在 SwiftUI 里，先抽 `Localizable.strings`（中英），再顺势支持系统语言 |
| README 首屏 GIF ⏳ | 静态截图看不出「动作连续」这个卖点，需要一段 6–8 秒录屏 |
| GitHub Actions ⏳ | `tag` 触发：编译 → 打包 → 上传 Release。签名证书走 Secrets，没有就跳过签名只出 dmg |

## v1.1 · 形象与收集

开源后第一眼的差异点，但不是信任问题，排在 v1.0 之后。

## v1.2 · 功能

| 事项 | 说明 |
|---|---|
| **喝水提醒** ⏳ | 用户明确要求推到这一版。设计草案见下 |
| 今日 / 本周久坐曲线 ⏳ | 纯本地统计，不上传。数据源就是每天的累计秒数，存 `UserDefaults` 环形缓冲 14 天 |
| 免打卡额度 ⏳ | 出差、休假期间连续天数容易断。给每月 2 天「豁免」，手动使用 |
| 轻提醒形态 ⏳ | 静默期间（看视频/线下会）的卡片可以更轻：角落小尺寸、半透明、不占焦点。v0.9.5 只做到「不升级、不追鼠标」 |

**喝水提醒设计草案**（沿用 D-21 的教训，先分清「记账」和「打扰」）：

- 和久坐**分开两个计时器**：坐姿时长 vs 距上次喝水时长
- 喝水是「事件」不是「时长」：点了「我喝了」就重置，不点也不强推
- **不做独立弹窗**，只在久坐卡片里带一句「顺手喝口水」。两个弹窗抢注意力会互相稀释
- 当日喝水次数藏进设置页「习惯」分组

## 更远 / 实验

- **动作补间**：每个动作只有 1 帧关键姿态，靠时序和停顿做「动」的错觉。真做中间帧要 AI 出序列（成本高、一致性差），短期不做
- **Sparkle 自动更新**：v1.0 之后再考虑，先靠 Release 页手动下载
- **Homebrew Cask**：`brew install --cask xiehuier`，需要一个稳定的 dmg URL 和 sha256
- **专注模式联动**：系统开了「勿扰」就自动免打扰。能做，但要在 README 写清是读系统状态而不是读你的通知内容

## 已知缺陷（诚实清单）

这些不是 TODO，是当前实现的天花板，写在 README 里比藏起来好：

| 缺陷 | 原因 | 缓解 |
|---|---|---|
| 线下围坐开会、戴耳机用手机开会 → 检测不到，照常弹提醒 | 会议检测只有「摄像头/麦克风被占用」一条正向证据 | 菜单里「暂停 1 小时」：记账不停、只是不提醒 |
| 人离开但屏幕没熄（没锁屏、还没到熄屏时间）→ 会多记几分钟 | 屏幕状态是唯一可靠的离开信号 | 一般 10 分钟内会熄屏；多记的代价是回来多点一次提醒 |
| 屏幕设成「永不休眠」时，只能靠 30 分钟时长兜底 | 拿不到熄屏信号 | 设置里把「兜底归零」调小 |
| 计时存在内存里（v0.9.6 修复中） | 没落盘 | 重启后从 0 开始 |

## 明确不做

| 事项 | 理由 |
|---|---|
| ~~全屏半透明遮盖~~ | 打断工作，会议共享屏幕时尤其糟糕。见 [D-12](DECISIONS.md#d-12--强提醒不做全屏遮盖改贴光标) |
| ~~Windows / Linux 版~~ | 核心依赖全是 macOS 专有行为（NSPanel 不抢焦点、`CGEventSource`、`.screenSaver` 层级、LaunchAgent），移植等于重写 |
| ~~读取你在用哪个 App~~ | 需要额外权限，且超出「提醒站起来」这个目标 |
| ~~摄像头 / 红外判断座位上有没有人~~ | 隐私成本远超收益。屏幕亮不亮已经是足够的替身信号（见 [D-19](DECISIONS.md#d-19--用屏幕状态替代时长猜测)） |
| ~~云同步打卡记录~~ | 引入账号和后端，和「零权限、纯本地」的定位冲突 |
| ~~App Store 上架~~ | 需要 App Sandbox，而 `CGEventSource` 空闲时长和 LaunchAgent 自启在沙盒下都受限 |
| ~~让用户自定义上传宠物图片~~ | 动作一致性极难保证（没对齐的图切帧会跳），会变成一堆「为什么我的猫在闪」的 issue |
